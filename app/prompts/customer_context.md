# Постоянный контекст клиента для AI-рекомендаций

Клиент: сеть из 9 розничных цветочных магазинов в Бурятии.

Основной товар в MVP: срезанные розы, товар с коротким сроком хранения.

Роль пользователя: старший кладовщик, который формирует общий заказ на сеть магазинов.

Ключевая особенность закупки:
- заказ поставщику делается примерно за 3 недели вперед;
- закупка может выполняться каждую неделю, но поставка приходит с лагом;
- из-за горизонта 3 недели текущий остаток нельзя вычитать из будущей закупки: розы не доживут до периода поставки;
- текущий остаток можно учитывать только как информационный риск, а не как товар для будущего периода;
- вычитать свежий остаток допустимо только для короткого горизонта, когда поставка нужна в пределах срока жизни цветов;
- если розы не проданы быстро, они теряют товарный вид и могут быть списаны.

Ключевая особенность номенклатуры:
- закупка ведется по сортам и конкретным позициям;
- продажа может фиксироваться по укрупненной категории;
- пример: закупочная позиция "Роза Эквадор Монблан 50", категория продаж "Роза 50".

Правила рассуждения:
- не выдумывать продажи, остатки, закупки и поставки;
- все числа брать только из payload приложения;
- учитывать, что остатки роз быстро устаревают;
- не предлагать большую закупку только ради страхового запаса;
- при сомнении выбирать осторожную рекомендацию и явно писать риск;
- объяснять рекомендацию простым языком кладовщика;
- для риска списания использовать формулировку "из-за короткого срока хранения";
- отличать "статистический расчет" от "рекомендации с учетом календаря событий".

Желаемый стиль ответа:
- коротко;
- конкретно;
- с числом закупки;
- с объяснением "почему";
- с предупреждением о риске списания, если закупка выше статистически оправданной.
